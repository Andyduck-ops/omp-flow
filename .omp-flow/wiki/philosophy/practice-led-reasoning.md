# 实践导向的推理

omp-flow 借用“实事求是、实践论、反对本本主义与形式主义”的方法论精神：事实不是用来
迁就流程的，流程是帮助人认识事实、作出决定并回到实践中检验结果的工具。

这里的目标不是增加一套必须背诵的口号，而是约束工作流中的判断方式。

## 从事实出发，而不是从规则出发

- 先确认具体目标、现有证据、真实约束和可能后果，再选择流程、角色与检查深度。
- 规范、模板、Gate、清单和 verdict 是积累经验后的工具，不是独立于事实的真理。
- 当规则的预期与可观察事实冲突时，先检查假设、适用范围和规则本身，不能为了完成
  形式而改写事实。
- 完成文档、跑完一轮审计或填满清单，只能证明动作发生过，不能证明问题已经解决。

## 具体问题具体分析

每次推进都应回答：当前要改变的决定是什么，真正不可接受的后果是什么，现阶段的
主要矛盾是什么？

权限越界、数据损坏、错误事实和核心链路失效通常需要严格处理；内部表达还能更完整、
可逆选择仍有未知项或非关键界面尚不优雅，不应仅凭“不完备”自动升级为阻塞。严谨度
应与后果、不可逆性和取证价值成比例。

## 实践—认识—再实践

1. 从仓库、运行结果、用户反馈和外部来源中取得事实。
2. 形成暂时性的解释、需求或设计，并明确仍在依赖哪些假设。
3. 通过实现、实验、验证或有限取证让认识接触现实。
4. 根据结果修正设计、流程或原有判断，而不是维护既有文本的权威。

研究、Brainstorm 和 QbD 可以往返，但每一轮都应有明确的认识增量或决策价值。若下一轮
不能合理改变一个具体决定，就应记录残余风险并由人决定接受、降级、推迟或停止，而不是
以“还可以继续研究”为理由自行延长流程。

## 用主要矛盾形成可修订的第一性锚

非琐碎任务展开广泛 Research 前，先从可观察现象中共同辨认当前最支配结果的矛盾：哪些
要求正在冲突，真正要保住的结果是什么，哪些后果不能牺牲。这个“第一性锚”用于筛选
值得研究的问题和决定何时已有足够认识，不是为方案制造不可质疑的理论起点。

价值、风险容忍和不可牺牲结果由人先表态，Agent 随后以最强反方、反例和后果链挑战；
技术事实由 Agent 先调查，证据倾向明显时可以先给建议，但必须同时说明 strongest
counter-case 和什么事实会推翻建议。Wiki 提供历史经验和反例，不替人确定当前矛盾。

第一性锚必须记录或至少公开其关键假设与修订条件。Research、实验或实现证据改变主要
矛盾时，应回到 Brainstorm 修订锚；这正是认识进步，不是流程失败。若某项新增工作既不
可能修订锚，也不改变具体决定或防止真实后果，它通常没有继续扩大的决策价值。

高强度 Grill 最适合用在形成或重写这个锚时。所谓高强度，是反方和因果追问足够强，
不是固定问题数量、穷尽所有分支或新增机器 Gate。明显机械、低歧义任务可以直接推进；
不应为了证明“做过第一性思考”而制造新的形式主义。

## 形式服务于结果

只在形式能够保存重要知识、防止真实失败、支持协作或使决定可验证时增加结构。发现
流程诱导 Agent 追求文档完备、角色表演或无限审计时，应修正流程，而不是要求实践迁就
流程。

安全边界仍然存在：涉及权限、数据完整性和不可恢复副作用时保持 fail-closed；非关键且
证据不足的观察可以隐藏、标记 unavailable、fail-soft 或进入后续工作。反对形式主义不
等于放弃纪律，而是要求纪律对真实结果负责。

## 短名词，少处方

“第一性锚定”“主要矛盾”“实践检验”“反形式主义”等方法论名词可以作为短认知锚点，
帮助不同 Agent 和人快速恢复共同语言。保留这些少量 token 有价值；把名词完全删除会让
方法只剩零散动作，难以解释为什么这样判断。

但名词之后应立即连接可执行责任、反证或验证后果，不能展开成模型必须逐步模仿的完整
思考脚本。模型能力、Harness 和实践会变化，过细的认知处方容易过时，也会把注意力从
问题转向遵守 Prompt。优先约束稳定事项：人的价值与责任、机械安全边界、输出责任、最强
反方义务和可观察验收；让模型在这些边界内使用能力，并用实践反馈修订方法。

这不是取消约束。权限、数据、身份、路径和不可恢复副作用等稳定硬边界仍然明确；应被
删减的是无法连接到已观察失效或验收场景、只为规定模型“怎样想”的沉积规则。静态测试
保护行为锚、正反合同与源/部署一致性，不冻结整段 Prompt，也不为通过词组断言反向堆文案。

## 人与 Agent 的分工

人负责目的、价值取舍、风险偏好和最终决定。Agent 负责寻找证据、暴露假设、挑战因果、
提出替代方案并说明不确定性。Agent 不应凭借流程角色取得无限返工权；人也不应把签字
当作替代判断的形式。

Agent 提议继续研究、审计或返工时，必须说明：新增工作可能改变什么决定，防止什么
具体后果，以及为什么较轻的降级或记录风险不足。建立不了这条因果链时，它只能是建议，
不能自动成为阻塞项。

## Wiki 是实践记忆，不是新教条

Wiki 保存已经受过实践检验、值得跨任务复用的项目知识。它可以帮助当前 Agent 抵抗通用
模型默认值，也可以让人看到过去为什么作出某个选择；但它可能过时或继承旧模型和旧流程
的偏置，不能静默替代当前事实和人的判断。

在形成问题或建议前，Agent 应读取与当前决定有关的最小 Wiki 主题，并把其中的历史经验
与当前代码、运行结果和用户目标对照。三者冲突时应公开冲突，由人决定沿用、修订或废弃
旧结论。Wiki 条目有出处和适用边界，完成“查过 Wiki”本身不构成正确性证据。

有效协作形成三角校准：仓库与 Wiki 提供实践证据，人提供目的、价值和风险取舍，Agent
提供假设、建议和反方挑战。减少提问不会自动减少模型偏置；未被公开的默认假设同样需要
在 shared-understanding checkpoint 中接受人的校准。

## 在 omp-flow 中的落点

- Workflow 说明这套共同判断原则及人的治理权。
- Router Skill 要求先识别实际任务、证据和风险，再选择所需角色与深度。
- Brainstorm、Research、Design、QbD、Implement 和 Review Skill 各自把原则翻译成与
  角色有关的停止条件和证据要求。
- Harness Agent 提示词使用可执行语言，例如“说明具体后果和可能改变的决定”，而不是
  只重复哲学口号。
- Hooks、状态栏和 Python runtime 继续只处理机械事实，不编码“主要矛盾”、重要性或
  人类风险偏好等语义判断。

这套原则本身也必须接受实践检验：若它不能减少无价值循环、不能改善决定或反而产生
新的仪式，就应依据观察继续修订。
