## Previous blockers rechecked

### Native flat and batch dispatch now use only authoritative fields

The OMP source defines flat dispatch as `agent`, `id`, `description`, `role`, and `assignment`,
and batch dispatch as top-level `agent`/`context` plus items containing `id`, `description`,
`role`, and `assignment`
(`reference/oh-my-pi/packages/coding-agent/src/task/types.ts:83-142`).

`src/omp/extension.ts:51-65` now reads only native `agent`/`role` and `assignment`; dispatch
identity comes from native `id`. The first nonblank assignment line must be the exact v1
`ompFlowDispatch` object. `src/omp/extension.ts:237-287` binds `actorId` to native `id` and
resolves the active runtime receipt through Python before comparing Bundle, entry, output,
normalized role, actor, receipt, predecessor, and predecessor output.

Independent adapter probes passed with both real wire shapes:

- flat reviewer: `{agent, id, assignment}`;
- batch reviewer: `{agent, context, tasks:[{id, role, assignment}]}`.

Plain prose, actor mismatch, predecessor-output tampering, a missing descriptor field, and a
terminal operation receipt all failed closed. An initial negative control using the executor
agent name `task` with a reviewer descriptor was correctly rejected for role mismatch; the valid
native batch reviewer shape uses top-level `agent: "reviewer"`.

### Reviewer/check predecessor correlation is mandatory

`templates/.omp-flow/scripts/common/operation_store.py:100-110` requires both `reviewer` and
`check` operations to supply a predecessor, then requires it to be completed, from the same task,
and owned by a different actor. Independent CLI probes confirmed:

- omitted predecessor rejects for `reviewer`;
- omitted predecessor rejects for `check`;
- same-actor reviewer rejects;
- active predecessor rejects;
- a completed predecessor from a different actor succeeds.

The assignment emitted by `operation start` begins with the strict descriptor and explicitly
renders Actor ID, predecessor receipt, and predecessor output/handoff. The descriptor contains
the same resolved predecessor output as the completed runtime operation.
