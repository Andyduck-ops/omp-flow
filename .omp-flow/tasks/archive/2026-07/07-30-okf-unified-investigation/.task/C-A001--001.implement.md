# C-A001--001 — Switch work, review, and gate coordination to runtime receipts

## Objective

Replace Python-owned semantic topology, evidence, Reference, context, and phase projections with
linked work/review/human-decision Concepts. Retain only the fail-closed mechanical runtime
guarantees approved in the design.

This row depends on `A-001` and may proceed in parallel with `B-A001--001` because it owns runtime
coordination rather than canonical role prose. It switches consumers before the final retirement
row deletes obsolete producers.

## Approved requirements

- PRD: Minimal mechanical runtime, Work and review as Concepts, Direct cutover.
- Acceptance criteria AC3, AC5, AC6, and AC9.
- Design: Work and review data flow, Human gates, Error behavior.
- QbD 1 treatments: reviewer independence, receipt correlation, required-entry failure, and no
  hidden Markdown state.

## Scope

In scope:

- canonical Python consumers currently responsible for context assembly, Reference selection,
  topology/work readiness, Evidence submission, gates, and lifecycle phase projection;
- opaque operation/dispatch receipts with task locator, entry path, role, actor identity,
  mechanical state, predecessor correlation, and optional external-action receipt;
- independent reviewer identity checks and duplicate/conflicting mechanical-side-effect
  prevention;
- path-based dispatch inputs and linked work, handoff, review, audit, and human-decision outputs;
- visible failure for missing required entry paths, stale sessions, actor mismatch, duplicate
  claims, and failed external operations.

Out of scope:

- storing requirements, summaries, verdict meaning, work order, dependency graphs, or phase
  semantics in runtime records;
- reading Markdown headings, lists, filenames, or frontmatter to reconstruct state;
- editing canonical role prose owned by `B-A001--001`;
- deleting unused legacy modules/files or completing broad documentation/test retirement, owned by
  `D-B001C001--001`;
- mutating the live Python control plane that must finish this legacy task; use canonical templates
  and isolated installed copies.

## Inputs and bindings

- `decision:semantic-knowledge-boundary`
- `interface:bundle-agent-entry`
- `brief:direct-cutover`
- `finding:legacy-projection-coupling`
- runtime interfaces from `A-001`

## Done conditions

1. Native dispatch accepts a task root, role, entry Concept, objective, and output boundary without
   a CSV row or generated context pack.
2. Work scheduling remains an agent decision from authored indexes; runtime does not compute a DAG
   or phase.
3. Implementation and independent review correlate through opaque native receipts, and the same
   actor cannot satisfy both identities.
4. Review and human decision meaning live only in linked Concepts; runtime completion does not
   manufacture a semantic verdict.
5. Duplicate external effects, unsafe paths, stale sessions, identity mismatches, and missing
   required receipts fail closed.
6. Consumers no longer require the semantic content of `task.json`, `tasks.csv`, `evidence.csv`,
   JSONL manifests, `context/index.json`, or Reference selector grammar.
7. Legacy producers may still exist until the final row, but no new Bundle-native operation
   dual-writes them.

## Verification

Run and report:

```text
npm run build

```

Exercise focused runtime cases in an isolated scratch project:

- confined entry-path acceptance/rejection;
- operation and predecessor receipt correlation;
- same-actor reviewer rejection;
- duplicate side-effect rejection;
- missing required entry and failed dispatch behavior;
- semantic review output without a CSV/verdict/phase mutation.

Do not assert Markdown headings or list shapes.

## Handoff

Report changed consumers, receipt shape and ownership, focused commands/results, every retained
mechanical invariant, and the now-unreferenced producers/commands ready for the final retirement
row.
