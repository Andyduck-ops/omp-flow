# B-A001--001 — Switch Agent knowledge entry and navigation contracts

## Objective

Switch canonical workflow guidance, Skills, agent templates, and source-acquisition instructions
from generated context packages to task Bundle and entry-Concept navigation. Agents must receive
paths, read normal Markdown, and follow only useful links.

This row depends on the Bundle/runtime entry interface created by `A-001`. It does not implement
work/review runtime correlation or delete the old control plane.

## Approved requirements

- PRD: Semantic navigation, Connected Explore, Work and review as Concepts.
- Acceptance criteria AC2, AC4, and AC10.
- Design: Agent entry interface, Explore data flow, Native dispatch interface.
- QbD 1 treatment: every assignment identifies its required entry Concept without turning optional
  links into a closed manifest.

## Scope

In scope:

- canonical shared phase Skills and workflow guidance;
- canonical OMP, Codex, and Claude agent definitions and deployment templates;
- Harness assignment contracts for brainstorm, research, design, implementation, review, and QbD;
- source acquisition as an ignored clone cache plus task-local Reference Concepts;
- direct Concept-path handoff, allowed-output boundaries, and best-effort optional links;
- template/deployment registration needed for new Bundle-native definitions.

Out of scope:

- parsing Concept bodies or indexes into phase, topology, status, or dependency state;
- adding fixed headings, list grammars, filename protocols, or required link closure;
- implementing receipt persistence or independent-review comparison, owned by `C-A001--001`;
- deleting legacy Skills, Hooks, commands, formats, or broad tests, owned by
  `D-B001C001--001`;
- rewriting the durable project Wiki with task-local implementation detail.

## Inputs and bindings

- `decision:semantic-knowledge-boundary`
- `interface:bundle-agent-entry`
- `brief:direct-cutover`
- `design.md`
- output interface from `A-001`

## Done conditions

1. Every canonical role assignment names the Bundle root, bounded objective, relevant entry
   Concept, output boundary, and native receipt when correlation matters.
2. Planning guidance supports the brainstorm/research spiral over one connected Bundle.
3. Implementers enter through a descriptive work Concept; reviewers enter through that work,
   its linked handoff, and changed code.
4. No canonical guidance asks Python to concatenate row JSON, JSONL manifests, indexed Context,
   rendered Reference XML, or all prior chat history.
5. External clones are described as acquisition cache; task Reference Concepts carry revision,
   anchors, interpretation, and links without mandatory source copying.
6. Missing required entry content is reported as a blocker; optional missing links remain
   tolerable.
7. No new Markdown parsing, validator, typed-edge graph, or encoded persistent identifier is
   introduced.

## Verification

Run and report:

```text
npm run build
git diff --check
```

In an isolated generated project, inspect one assignment for each role family:

- explore/design;
- implementation;
- independent review/QbD.

Confirm that each can start from its supplied entry path and that no generated context manifest
or legacy fallback is needed. These are bounded assignment observations, not a permanent
Markdown-structure test matrix.

## Handoff

Report every canonical definition changed, scratch assignment examples, build results, any
deployment copy intentionally deferred until cutover, and any consumer still using the old
context contract for `D-B001C001--001` to retire.
