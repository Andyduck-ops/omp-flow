# A-001 — Create the semantic Bundle scaffold and minimal runtime kernel

## Objective

Create the canonical task-root OKF v0.2 scaffold and the smallest runtime primitives required by
the approved semantic/mechanical boundary. This row establishes interfaces consumed by the two
wave-2 rows; it does not switch every legacy consumer or delete any legacy store.

## Approved requirements

- PRD: One semantic task Bundle, Minimal mechanical runtime, Versioning and portability.
- Acceptance criteria AC1, AC6, and the mechanical portions of AC9.
- Design: Target task map, Runtime kernel ownership, Bundle creation, Bundle selection, Archive.
- QbD 1 risk treatments: preserve confined paths, session identity, atomic operations, and native
  correlation without moving semantic knowledge into runtime state.

## Scope

In scope:

- canonical Python templates that create, select, and archive task directories;
- new minimal modules or functions for Bundle scaffolding and runtime operation receipts;
- root `index.md` with `okf_version: "0.2"` and the smallest useful typed Concepts;
- ignored runtime/session placement outside the portable Bundle;
- confined entry paths, atomic create/select/archive primitives, and opaque operation identity;
- isolated scratch fixtures or focused mechanical checks owned by these primitives.

Out of scope:

- regular-expression, fixed-heading, list-shape, link-closure, or general YAML/Markdown parsing;
- switching platform Skills and agent cards, owned by `B-A001--001`;
- replacing work/review/gate consumers, owned by `C-A001--001`;
- deleting old files, changing the final Git ignore policy, broad fixture rewrites, or the
  end-to-end dogfood, owned by `D-B001C001--001`;
- changing the live `.omp-flow/scripts` runtime that is executing this legacy task. Validate the
  canonical templates through an isolated scratch installation.

## Inputs and bindings

## Done conditions

1. The canonical new-task path creates a Bundle root, root index, task/framing Concepts, and only
   directories that immediately aid navigation.
2. It does not generate empty CSV/JSONL ledgers, `task.json`, `context/index.json`, paired
   Reference metadata, `.task/`, or `.summaries/`.
3. Python validates task/session paths and mechanical identities but does not read Markdown
   semantics.
4. Runtime operation data contains no summaries, topology, verdict prose, phase meaning, or
   knowledge links.
5. Create/select/archive operations remain atomic and fail visibly on unsafe or conflicting
   mechanical state.
6. Canonical deployment can be exercised in an isolated scratch repository without modifying the
   control plane of this active legacy task.

## Verification

Run and report:

```text
npm run build
```

Run the focused scratch checks introduced or adapted by this row for:

- new Bundle seed shape;
- path confinement;
- active-session selection;
- opaque receipt uniqueness/correlation;
- atomic create/archive failure behavior.

Inspect the generated Bundle directly to confirm that it is readable, uses ordinary links, and
contains no legacy control files. Do not add a reusable Markdown schema validator for that
inspection.

## Handoff

Report changed files, exported/runtime interfaces used by later rows, scratch commands and
results, mechanical failure cases exercised, and any old consumer deliberately left untouched.
