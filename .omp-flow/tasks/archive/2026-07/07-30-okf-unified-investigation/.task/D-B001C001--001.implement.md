# D-B001C001--001 — Retire legacy stores and prove the direct cutover

## Objective

Complete the consumer-first cutover after `B-A001--001` and `C-A001--001`: remove obsolete
producers, formats, commands, protections, and tests; adopt Git-visible task Bundles; and prove the
new architecture with one isolated end-to-end dogfood task.

This is the integration and release row. It must not restore compatibility or convert the legacy
schemas into Markdown.

## Approved requirements

- All PRD requirements and acceptance criteria, especially AC7 and AC8.
- Design: Versioning, Cutover design, Verification, Retirement verification.
- QbD 1 treatments: complete consumer inventory, no dual write/fallback, Git/cache boundary,
  proportional mechanics checks, and end-to-end semantic dogfood.

## Scope

In scope:

- delete legacy task-state, topology, Evidence, context-manifest, Reference-digest, gate-phase, and
  amendment producers/commands after proving no active Bundle-native consumer remains;
- stop seeding `task.json`, CSV, JSONL, `context/index.json`, paired metadata, `.task/`, and
  `.summaries/`;
- update canonical deployment source, CLI init/update behavior, Hooks/protection rules, workflow
  documentation, package fixtures, and tests to the final model;
- change ignore policy so new task Bundles and archives are Git-visible while runtime/session data
  and external clone caches remain ignored;
- preserve legacy task material only as immutable historical files outside the new runtime
  contract, with no permanent reader;
- run a newly generated isolated project through Explore, Design, human decision, grouped work,
  implementation handoff, independent review, and archive using Bundle links and native receipts.

Out of scope:

- bulk translating historical task archives;
- compatibility fallbacks, dual-write mode, Markdown parsers, topology IDs, or schema closure
  tests;
- changing native Harness process/concurrency semantics;
- treating this active legacy task's deployed control plane as the dogfood environment. Use a
  scratch installation so this task can finish and archive truthfully.

## Inputs and bindings

- `decision:semantic-knowledge-boundary`
- `brief:direct-cutover`
- `finding:legacy-projection-coupling`
- handoffs from `B-A001--001` and `C-A001--001`
- `prd.md`, `design.md`, and QbD 1 audit treatments

## Done conditions

1. New task scaffolding contains the OKF Bundle entry and no retired strong-format files or empty
   replacement ledgers.
2. Active source, templates, Hooks, Skills, agent cards, docs, and tests have no legacy consumer or
   fallback; remaining text matches are explicitly historical examples.
3. Bundle edits and archive relocation are visible to normal repository Git; runtime/session and
   clone-cache changes are not.
4. The isolated dogfood task alternates brainstorm/research, navigates from indexes and links,
   records a human decision, dispatches grouped descriptive work, produces a linked handoff and
   independent review, and archives with working relative navigation.
5. The dogfood does not rely on a fixed heading/list shape, encoded filename, context manifest,
   Reference selector, CSV/JSONL ledger, or Markdown semantic parser.
6. Focused checks pass for path confinement, session selection, receipt identity, reviewer
   independence, duplicate-side-effect prevention, and atomic create/archive.
7. Package build, tests, scratch initialization/update, and package-content checks pass.
8. No accepted state dual-writes old and new models.

consumer-search observations, Git ignore behavior, any immutable legacy placement, and any
remaining release risk. A successful handoff moves to independent review; it does not self-approve
the cutover.
