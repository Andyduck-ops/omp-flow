# C-A001--001 handoff

Status: DONE

## Outcome

Canonical work, review, and dispatch coordination now enters through task Bundle paths and opaque
runtime operations. The canonical CLI no longer imports or exposes the semantic context,
Reference, topology, Evidence, gate, amendment, lifecycle, doctor, or disposition paths.

The OMP adapter no longer extracts exact row IDs from prompt text or asks Python to render a
context package. The coordinator first starts an operation through Python, which returns an
assignment whose first nonblank line is a strict v1 JSON descriptor. The native task call passes
that assignment unchanged through the authoritative `id` / `description` / `role` / `assignment`
item schema. The extension parses only the descriptor, binds its `actorId` to native `id`, and
verifies every mechanical field against the active runtime operation.

The descriptor and readable assignment both contain the Bundle root, entry Concept, objective,
output boundary, role, actor ID, operation receipt, predecessor receipt, and resolved predecessor
output/handoff. A Review operation cannot be created without a completed predecessor.

## Receipt ownership and shape

Runtime owns records under ignored `.omp-flow/.runtime/`:

- `operations/<opaque-id>.json`: `id`, `task_id`, `entry_path`, `output_path`, `role`,
  `actor_id`, `state`, `predecessor`, `requires_external_receipt`, `external_receipt`, and
  timestamps;
- `receipts/<sha256>.json`: exclusive external-side-effect claim;
- `locks/operation-<opaque-id>.lock`: fail-closed terminal-update exclusion.

The operation record deliberately does not contain objective text, verdict meaning, phase,
topology, requirements, dependency semantics, review meaning, or a Markdown-derived field.
Objective text is transient in the native assignment. Review and human-decision meaning remain
only in authored linked Concepts.

## Retained mechanical invariants

- session identity must exist, be non-stale, and match any explicitly requested task;
- entry Concepts must exist inside the selected task Bundle;
- output boundaries must remain inside the repository;
- missing entries and unsafe paths fail before a receipt is created;
- predecessor receipts must exist, belong to the same task, and be completed;
- Review roles cannot omit the predecessor receipt;
- an independent reviewer cannot reuse the predecessor actor identity;
- the dispatch descriptor actor must equal the native task item `id`;
- descriptor Bundle, entry, output, role, receipt, predecessor, and predecessor output must match
  the active operation exactly;
- plain prose, malformed JSON, unknown descriptor fields, missing descriptor fields, or a stale
  receipt fail before native spawn;
- only the bound actor can finish an operation;
- successful completion can require a non-empty native/external receipt;
- external receipts are claimed atomically and cannot be reused by another operation;
- terminal writes are serialized; a crashed lock or incomplete receipt claim remains
  fail-closed;
- failed dispatches can be recorded mechanically as `failed` without manufacturing semantic
  task state.
